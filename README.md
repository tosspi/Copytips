--------------------------------------------------
1. 它能做什么  
- 监听系统剪贴板，只要出现 **新的非空文本** → 立即在屏幕底部中央弹出 **“Copied”** 提示  
- 判定口径（2.3.0 起默认 **内容驱动**）：**内容变了就提示**，不区分这段文本是 `Ctrl+C` 复制的、右键菜单“复制”的，还是别的程序写进来的（选中即复制、剪贴板管理器、脚本写入同样提示）；同一内容 500 ms 内重复写入只提示一次  
- 需要回到 2.1/2.2 的“只认复制动作”口径时，用 `COPYTIPS_MODE=strict` 启动（见第 9 节），两种模式的钩子采集完全一样，便于 A/B 对照  
- 2 秒后自动消失，全程无焦点、无声音  
- 托盘右键可 **开机自启 / 退出**

- **深色半透明圆角胶囊**（#202128，约 66% 不透明度）+ 13% 白色内描边 + 柔和投影  
- **翠绿对勾 + 白色 “Copied”**，Segoe UI Semibold 13px，按 DPI 缩放；文字满不透明，主体半透明也不牺牲可读性  
- 尺寸紧凑（窗口约 107×46，胶囊约 93×32），固定在任务栏上方 16 px，不跟随鼠标，**不遮挡任务栏**（任务栏自动隐藏时按任务栏真实位置避让）

4. 版本号规则  
采用 `主版本.次版本.修订号`（SemVer 2.0.0），版本号只在 `version.h` 一处维护，源码与资源文件都从它读取：

| 段位 | 何时递增 | 例子 |
|---|---|---|
| **主版本** | 用户可感知的行为或形态大改，旧观感/用法不再成立 | 方窗 → 圆角胶囊 |
| **次版本** | 视觉风格或新能力调整，用法完全兼容 | 更小 + 半透明 |
| **修订号** | 只修 bug / 只调参数，不改外观也不改行为 | 修正描边亮度 |

**每次改动都必须至少递增其中一段，不允许改了代码却不改版本号。** 版本号会出现在文件属性（右键 → 详细信息）和托盘图标的悬停提示里。

| 版本 | 变化 |
|---|---|
| 2.3.0 | 触发条件改为**内容驱动**（默认）：剪贴板出现新的非空文本就提示，不再要求先检测到复制按键；用内容指纹（FNV-1a 64）+ 长度 + 500 ms 窗口去重，新增结论 `SKIP_DUPCONTENT`。设 `COPYTIPS_MODE=strict` 可回到 2.2.1 的意图驱动，用于对照与回退。日志新增 `hash=` 字段与启动行的 `mode=` |
| 2.2.1 | 加**诊断日志**（默认关闭）：三路开关（`COPYTIPS_DEBUG` / `--debug` / exe 旁 `copytips.debug`），逐事件写 `%TEMP%\copytips.log`，记录序列号、各意图信号的时间差、菜单模式、剪贴板 owner/前台窗口、格式列表、文本长度与开头；判定条件与 2.2.0 完全一致 |
| 2.2.0 | 补齐三个场景：右键菜单“复制”也会提示（鼠标钩子记录右键抬起时刻，覆盖传统与自绘菜单）；管理员权限窗口里复制也能提示（40 ms 轮询 `GetAsyncKeyState` 兜底 UIPI）；误报面收窄（复制窗口 1500 → 400 ms、远程桌面自适应放宽，并新增“写入者必须是前台进程”校验） |

7. 已知限制（2.3.0 起）  
- **默认模式不区分“谁写的”**：程序化写入也会提示——`Set-Clipboard` 等脚本、密码管理器、手机剪贴板同步、输入法的“最近复制”列表，只要写入了新的非空文本就会弹一次。这是内容驱动的固有口径，需要更严的行为请用 `COPYTIPS_MODE=strict`。 尤其是**拖选即写剪贴板**的程序——终端里的选中即复制、词典/翻译工具的取词、部分聊天工具的划词——在默认模式下同样会弹，这是内容驱动的直接后果，不是故障。  
- **同一内容 500 ms 内只提示一次**：连按两次 `Ctrl+C` 复制**同一段**文字，第二次不提示（`CONTENT_DEDUPE_MS`）；换一段内容、或间隔超过 500 ms，就正常提示。 去重窗口是从**上次提示的时刻**起算，不是滑动窗口：若某程序按固定间隔持续重写同一段文本，会呈现每 500 ms 以上弹一次的周期性提示。  
- **超长文本只有前 1,048,576 个字符参与指纹**（受扫描上限 `LOG_SCAN_MAX_CHARS` 约束；`CONTENT_HASH_MAX` 当前与它同值）：两段这样长的文本若只有尾部不同，会被判为同一内容而漏一次提示。取舍是为了不让剪贴板事件在 UI 线程上走长循环。  
- **严格模式（`COPYTIPS_MODE=strict`）保留 2.2.0/2.2.1 的全部限制**：极短的按键可能漏检（管理员窗口靠 40 ms 轮询兜底）；右键抬起后 2.5 秒内的写入会被当成复制；按下复制键但目标程序没复制时 400 ms 内仍可能误认；经代理进程写剪贴板的程序（部分 UWP）可能不提示。

8. 诊断日志（2.2.1 起）  
默认**关闭**；关闭时主路径仅多一次约 200 B 的栈清零（纳秒级），可忽略。开启方式三选一：

| 方式 | 做法 |
|---|---|
| 环境变量 | `set COPYTIPS_DEBUG=1` 后启动（值写 `0` 等于关闭） |
| 命令行 | `copytips.exe /debug` 或 `copytips.exe --debug` |
| 标记文件 | 在 `copytips.exe` 同目录放一个空文件 `copytips.debug` |

- **日志位置**：`%TEMP%\copytips.log`（UTF-8 带 BOM，记事本直接打开；超过 2 MB 时旧日志轮转为 `copytips.log.1`）  
- **启动一行**：`[时间] [startup] ver=2.3.0 mode=loose dpi=96 rdp=0 keyhook=1 mousehook=1 debug=1 log=<路径>`（`mode` 为 `loose` / `strict`）  
- **每次剪贴板事件一行**（无论最终是否弹窗），例如：

```
[2026-11-04 21:40:12.345] seq=8123 dtKey=-1 dtMenu=311 dtLUp=980 dtRUp=311 mFlag=menu owner=WeChatMainWndForPC#11884 ownerVis=1 fg=WeChatMainWndForPC#11884 fmt=1:TEXT,13:UNICODETEXT,16:LOCALE hash=A635B8B02A57D24B len=12 head="今天下午三点开会讨论方案" decision=SHOW
```

> 定位「误弹」先看启动行的 `mode=`：
> - `mode=loose`（默认）：`SHOW` 行本来就不需要按键证据，`dtKey=-1` 是正常的；要判断“为什么没提示”就看是不是 `SKIP_DUPCONTENT`（内容没变）或 `SKIP_EMPTY`（不是文本）。
> - `mode=strict`：看 `decision=SHOW` 行的 `dtKey` / `dtMenu`——`dtKey=42` 说明是 42 ms 前刚按下的复制键（真实复制通常 <50 ms），`dtMenu=1800` 说明是 1.8 秒前的右键抬起在起作用（菜单窗口 2500 ms）。`-1` 表示该信号**从未触发过**（两个都是 `-1` 却仍然 `SHOW`，说明两个钩子都没装上，去看 `[startup]` 行的 `keyhook/mousehook`）。

| 字段 | 含义 |
|---|---|
| `seq` | 剪贴板序列号（每次写入 +1，用于去重） |
| `dtKey` | 距最近一次复制快捷键（Ctrl+C/X/Insert、Shift+Del）的毫秒数；`-1` = 该信号从未触发过。SHOW 行会给出真实差值，`0~400`（远程桌面 `0~1500`）说明就是刚按下的快捷键 |
| `dtMenu` | 距最近一次右键抬起的毫秒数（右键菜单“复制”靠它）；`-1` = 该信号从未触发过，`0~2500` 说明命中的是菜单那一条 |
| `dtLUp` / `dtRUp` | 距最近一次左键 / 右键抬起的毫秒数，`-1` = 从未 |
| `mFlag` | 抬起瞬间前台线程是否处于菜单模式（`menu` / `nomenu`），仅旁证 |
| `owner` | 剪贴板写入者窗口的类名 `#` 进程号；`none#0` = 没有 owner |
| `ownerVis` | owner 窗口是否可见（`1` / `0`），仅记录 |
| `fg` | 当前前台窗口的类名 `#` 进程号 |
| `fmt` | 剪贴板里可用的格式（最多 8 个；有 `13:UNICODETEXT` 才是文本） |
| `hash` | 文本内容指纹（FNV-1a 64，16 位十六进制，带长度一起构成去重键）；`0000000000000000` 表示本次**没有算出指纹**——重复通知（`SKIP_SEQ`，补读取格式、长度与开头）或没读到文本（`SKIP_EMPTY` / `SKIP_CLIPBUSY`） |
| `len` / `head` | 文本字符数、开头 32 个字符（`\r` `\n` `\t` 与双引号已转义，超长补 `...`） |
| `decision` | `SHOW`（弹窗）/ `SKIP_SEQ`（同一次写入的重复通知）/ `SKIP_EMPTY`（不是文本或内容为空）/ `SKIP_CLIPBUSY`（剪贴板被别的进程占着）/ `SKIP_DUPCONTENT`（宽松模式：内容与上次提示过的一样且没过 500 ms）/ `SKIP_NOINTENT`、`SKIP_OWNER`（仅严格模式） |

- **性能**：开启后每个剪贴板事件会在 UI 线程多做一次文件写 + 一次只读的剪贴板采集（约 1 ms 量级），低层钩子的回调也会相应延后同量级——只适合排查期间短时间开启。

> **用完记得关掉**：删掉 exe 同目录的 `copytips.debug`（或去掉环境变量 / 命令行参数）即可。日志会记录剪贴板文本开头 32 个字符，**排查完请顺手删掉 `copytips.log`**。

9. 触发模式（2.3.0 起）  
启动时读一次环境变量 `COPYTIPS_MODE`，之后不再变化：

| 取值 | 模式 | 行为 |
|---|---|---|
| 未设置 / 空 / 其它任何值 | **宽松（默认）** | 剪贴板出现新的非空文本就提示；内容指纹 + 长度 + 500 ms 窗口去重 |
| `strict`（大小写不敏感） | **严格** | 2.2.1 的意图驱动：`Ctrl+C` / `Ctrl+X` / `Ctrl+Insert` / `Shift+Delete`、右键菜单“复制”（抬起后 2.5 s 内），且写入者必须是前台进程；不做内容去重 |

```cmd
set COPYTIPS_MODE=strict
copytips.exe
```
- 两套模式的**钩子安装与旁证采样完全相同**，差异只在判定链，所以同一份日志可以横向对比。
- 严格模式的**判定结论**与 2.2.1 等价（同一份现场该弹的都弹、不该弹的都不弹），但实现顺序是「先读内容 → 再判意图 → 再判写入者」：因此「空文本 / 剪贴板被占用且无意图」会记成 `SKIP_EMPTY` / `SKIP_CLIPBUSY`（2.2.1 记 `SKIP_NOINTENT`），且每个非重复事件都会读一次剪贴板。
- 环境变量只影响新启动的实例：改了之后要退出重开（`InitPromptMode` 只在启动时算一次）。
